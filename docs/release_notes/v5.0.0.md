# Announcing spice-rs v5.0.0 🎉

v5.0.0 moves the SDK to Arrow 59, lets you bind dates, times, and durations directly as query parameters, and makes connections more reliable: parameterized queries now work with API keys, and idle or busy connections recover from resets.

## Upgrading from v4

**Arrow 59.** The SDK now uses Arrow 59 (previously 58). If your application also depends on `arrow`, move it to the same version; otherwise, passing Arrow values to or from the SDK fails to compile with errors such as `expected arrow::array::RecordBatch, found spiceai::arrow::array::RecordBatch`.

```toml
[dependencies]
spiceai = "5"
arrow = "59"
```

Alternatively, import Arrow through `spiceai::arrow`, which always matches the SDK's version. No other APIs were removed or changed.

If you match on error variants: a query that still fails with a connection reset after all retries now returns `Error::ConnectionReset` instead of `Error::Query`. ([#98](https://github.com/spiceai/spice-rs/pull/98))

## What's New

### Date and time query parameters

Bind `chrono` and `std::time` values directly, without building Arrow arrays:

```rust
use std::time::Duration;
use spiceai::chrono::{TimeZone, Utc};
use spiceai::{QueryParameter, QueryParameters};

let since = Utc.with_ymd_and_hms(2024, 1, 31, 0, 0, 0).unwrap();
let params = QueryParameters::new()
    .push(QueryParameter::try_from(since)?)
    .push(QueryParameter::try_from(Duration::from_secs(30 * 60))?);

let stream = client
    .sql_with_bindings(
        "SELECT * FROM trips WHERE pickup_time >= $1 AND trip_duration > $2",
        params,
    )
    .await?;
```

Supported types: `DateTime<Tz>`, `SystemTime`, `NaiveDateTime`, `NaiveDate`, `NaiveTime`, `std::time::Duration`, and `chrono::TimeDelta`. A timestamp outside 1677–2262, a duration over about 292 years, or a leap second returns an error rather than a different value; any `NaiveDate` binds. `chrono` is re-exported as `spiceai::chrono`. ([#106](https://github.com/spiceai/spice-rs/pull/106))

## Fixes

- Parameterized queries (`sql_with_params()`, `sql_with_bindings()`) now work with Spice Cloud and any runtime that requires an API key. The client also authenticates once and reuses the session instead of authenticating before every query. ([#100](https://github.com/spiceai/spice-rs/pull/100))
- HTTP-based methods such as `is_ready()`, `search()`, `nsql()`, and `query()` now work without `http_url()`: they connect to `http://localhost:8090` by default, or to `https://data.spiceai.io` with `use_spiceai_cloud()`. For any other runtime, set `http_url()`. ([#99](https://github.com/spiceai/spice-rs/pull/99))
- Running many parameterized queries concurrently no longer causes the runtime to close the connection. ([#109](https://github.com/spiceai/spice-rs/pull/109))
- Idle connections stay open behind load balancers and private links, and queries, including parameterized queries and authentication, retry automatically after a connection reset. An invalid API key still fails immediately. ([#96](https://github.com/spiceai/spice-rs/pull/96), [#97](https://github.com/spiceai/spice-rs/pull/97))
- `search()` now returns an error when the response is not a valid search result, instead of an empty result. ([#105](https://github.com/spiceai/spice-rs/pull/105))
- `cache_control()` now applies to HTTP requests as well as SQL queries. ([#104](https://github.com/spiceai/spice-rs/pull/104))
- Errors now include the reason when a response body cannot be read. ([#95](https://github.com/spiceai/spice-rs/pull/95))

## Dependencies

- `arrow`, `arrow-flight`, and `arrow-json` upgraded to 59.3. ([#103](https://github.com/spiceai/spice-rs/pull/103))
- `webpki-roots` 1.0.10 or later is required, which removes the emSign ECC Root CA - G3 certificate. ([#108](https://github.com/spiceai/spice-rs/pull/108))
